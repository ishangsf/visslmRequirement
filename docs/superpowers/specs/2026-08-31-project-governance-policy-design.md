# 项目治理策略配置设计

## 1. 背景与目标

项目管理模块已经能够基于固定规则生成交付、成本、计划、追溯和 AI 运行治理提醒，并支持参与人确认知悉。当前阈值直接固化在治理报告实现中，无法表达不同组织或项目的风险偏好，也无法审计某条提醒采用了哪套策略。

本阶段建立“全局默认 + 项目覆盖”的版本化治理策略。系统设置维护全局默认值，项目仅覆盖确有差异的字段；治理报告公开最终生效值、版本和逐字段来源。策略修改必须可追溯，并使用乐观并发避免静默覆盖。

本阶段不实现外部或应用内通知投递、升级消息、模型单价和 AI 成本核算。

## 2. 范围

### 2.1 包含

- 版本化全局治理策略。
- 稀疏、版本化的项目治理策略覆盖。
- 项目覆盖保存、取消覆盖和审计。
- 治理报告按生效策略计算提醒等级和复核 SLA。
- 系统设置中的全局策略编辑界面。
- 项目治理页中的策略来源、项目覆盖和审计界面。
- Snapshot v2、Excel 导出、迁移和兼容处理。
- 动态、静态 UI、导出、类型和生产构建回归。

### 2.2 不包含

- 邮件、Webhook、钉钉、系统通知或站内消息投递。
- 提醒升级、催办调度或后台定时扫描。
- 模型价格目录、Token 费用或字符费用换算。
- 项目管理以外模块的治理阈值。
- 多用户身份认证或新的权限系统。

## 3. 策略字段与默认值

策略包含以下字段：

| 字段 | 默认值 | 合法范围 | 含义 |
| --- | ---: | ---: | --- |
| `riskWarningThreshold` | `0.50` | `0–1` | 风险系数达到此值时产生 warning |
| `riskCriticalThreshold` | `0.75` | `0–1` | 风险系数达到此值时产生 critical |
| `estimatedCostWarningRatio` | `1.00` | `0.5–5` | 预计成本/合同金额达到此比例时产生 warning |
| `actualCostCriticalRatio` | `1.00` | `0.5–5` | 实际成本/合同金额达到此比例时产生 critical |
| `reviewDueSoonDays` | `3` | `0–30` 的整数 | 开放复核在此天数内到期时计入 due soon |
| `taskOverdueCriticalDays` | `7` | `1–365` 的整数 | 未完成任务逾期达到此天数时由 warning 升级为 critical |

`riskWarningThreshold` 必须严格小于 `riskCriticalThreshold`。成本比例仅在 `contractAmount > 0` 时参与计算。

项目交付临近继续使用项目现有的 `deliveryReminderDays`。任务阻塞始终是 critical。追溯复核逾期、失效关系、未分派关系和当前基线 AI 复核失败保持现有规则；仅复核 due-soon 天数改由策略控制。

## 4. 数据模型

### 4.1 版本化策略

新增统一的策略版本存储，支持 `global` 和 `project` 两种作用域。每次保存都追加版本，不原地覆盖历史。

每个版本至少保存：

- 唯一 ID。
- 作用域。
- 项目 ID；全局版本为空。
- 作用域内递增版本号。
- 项目版本创建时所基于的全局版本号。
- 策略 JSON；全局版本为完整值，项目版本为稀疏覆盖。
- 是否启用项目覆盖；取消覆盖通过追加禁用版本表达。
- 操作者参与人 ID 和名称；全局版本使用“本机系统设置”来源。
- 修改原因。
- 创建时间。

数据库迁移必须幂等。没有全局版本时创建默认 V1。损坏、缺字段或越界版本不得参与运行；系统回退最近一个完整有效的全局版本，最终才回退代码默认值，并向设置界面暴露配置错误。

### 4.2 生效策略

读取项目策略时：

1. 读取最新有效全局版本。
2. 读取项目最新版本。
3. 若项目版本启用，将稀疏字段覆盖到全局值；若禁用则完全继承全局。
4. 再次验证合并结果。
5. 返回最终值、全局版本、项目覆盖版本，以及每个字段的 `global` 或 `project` 来源。

取消项目覆盖不会删除历史，而是追加一个禁用版本。

### 4.3 审计

版本行本身构成不可变策略审计来源。公共审计 DTO 展开以下信息：作用域、版本、操作者、原因、修改前值、修改后值、创建时间。项目覆盖的保存和取消必须选择当前项目参与人并填写非空原因。全局保存记录为“本机系统设置”，不依赖项目参与人。

## 5. 治理规则集成

治理报告必须先解析生效策略，再计算提醒和 SLA，并返回策略快照：

- `globalVersion`
- `projectOverrideVersion`
- `effectiveValues`
- `fieldSources`
- `evaluatedAt`
- 配置错误列表

规则调整如下：

- `riskFactor >= riskCriticalThreshold`：critical。
- 否则 `riskFactor >= riskWarningThreshold`：warning。
- `contractAmount > 0` 且 `(estimatedCost + laborEstimatedCost) / contractAmount >= estimatedCostWarningRatio`：warning。
- `contractAmount > 0` 且 `actualCost / contractAmount >= actualCostCriticalRatio`：critical。
- 未完成任务逾期天数达到 `taskOverdueCriticalDays`：critical；否则仍为 warning。
- 开放复核距离截止日期 `0..reviewDueSoonDays` 天：计入 due soon。

提醒键只包含对应规则实际使用的阈值和业务身份。例如风险提醒包含适用的风险阈值，任务逾期提醒包含升级天数。修改无关策略字段不得改变其他提醒键；修改相关阈值导致提醒规则或等级重新求值时，新的提醒需要重新确认。

## 6. API 与并发控制

公共能力分为全局和项目两组：

- 读取当前全局策略和错误。
- 保存新的全局策略版本。
- 读取项目生效策略与项目策略审计。
- 保存项目稀疏覆盖。
- 取消项目覆盖。

保存请求携带页面读取时的当前版本号。服务端在事务中比较最新版本：版本不一致则拒绝保存，返回明确的“策略已更新，请刷新后重试”错误，不进行部分写入。

项目保存和取消覆盖必须验证操作者是当前项目参与人。稀疏覆盖仅允许已知字段；空覆盖等同于取消覆盖，但仍使用显式取消接口以保持审计语义清晰。

## 7. 界面设计

### 7.1 系统设置

系统设置新增“项目治理”页：

- 展示当前全局版本和更新时间。
- 使用纵向表单编辑六项阈值。
- 在控件旁显示单位、合法范围和规则说明。
- 保存时展示校验错误和并发冲突。
- 配置损坏回退时展示不可忽略的 warning 和实际生效版本。

### 7.2 项目治理页

项目治理页增加“策略设置”入口：

- 默认展示六项最终生效值及逐字段来源。
- 用户勾选需要项目覆盖的字段；未勾选字段继续继承全局。
- 保存时选择项目参与人并填写原因。
- 支持取消全部覆盖，明确说明将恢复继承当前全局值。
- 展示项目策略审计表，使用统一可调整列宽、版本化缓存和响应式内部滚动。
- 保存成功后刷新治理报告和提醒列表。

界面继续遵守现有暗色/亮色主题变量、4px 间距体系、响应式表单、内部滚动和键盘可访问要求。

## 8. Snapshot 与 Excel

Snapshot v2 新增：

- 项目策略版本历史。
- 项目策略审计所需的操作者快照。
- 导出时的全局版本和最终生效策略快照。

全局策略历史不随单个项目导出。

导入仅恢复项目的稀疏覆盖语义；未覆盖字段使用目标环境当前全局策略。如果源快照的全局版本或最终继承值与目标环境不同，导入返回 warning，并在治理页说明继承值已重新计算。策略审计中的参与人尽可能通过参与人映射恢复；缺失参与人保留名称快照并产生 warning，不伪造当前参与人身份。

Excel“项目治理”工作表增加：

- 生效策略版本与逐字段来源。
- 六项生效值。
- 项目策略变更审计行。
- 原有提醒、确认、SLA 和 AI 用量行。

## 9. 错误处理

- 非法输入在写事务前拒绝，零写入。
- 并发版本冲突零写入并要求刷新。
- 非项目参与人不能保存或取消项目覆盖。
- 损坏存储版本不参与计算，并返回配置错误。
- 导入缺失引用产生 warning 并跳过对应审计身份映射；不得中止其他合法数据。
- v1 和缺少策略字段的旧 v2 快照继续导入，项目默认继承目标环境全局策略。

## 10. 验收与测试

### 10.1 动态行为

- 固定本地日期验证默认策略、全局新版本、项目稀疏覆盖和取消覆盖。
- 覆盖六项边界值、越界值、非整数天数和风险阈值顺序错误。
- 验证成本比例仅在合同金额大于 0 时生效。
- 验证任务逾期 warning/critical 分界及复核 due-soon 边界。
- 验证相关阈值变化会重新求值提醒键，无关阈值变化不破坏已有确认。
- 验证非参与人、空原因和过期版本零写入。
- 验证版本追加、前后值、操作者和取消覆盖审计。
- 验证迁移和多次重启幂等。

### 10.2 导入导出

- Snapshot v2 导出策略历史和生效快照。
- 导入恢复稀疏覆盖并对全局差异产生 warning。
- 参与人身份正确映射；缺失身份保留名称并 warning。
- v1、旧 v2 和缺少策略数组的快照兼容。
- Excel 包含策略版本、值、来源和审计；空数据仍保留表头。

### 10.3 UI 与构建

- 系统设置和项目治理页覆盖 loading、error、保存中、并发冲突和回退 warning。
- 验证暗色/亮色、全屏及 1200/1000/760/680px 布局。
- 验证表格列宽拖拽、键盘调整、缓存恢复和内部纵向滚动。
- 运行 TypeScript、项目管理动态 smoke、两组 UI smoke、Excel 导出 smoke 和生产构建。

## 11. 交付边界

本设计完成后，项目治理提醒具有可配置、可解释、可审计的规则来源。通知调度、消息投递和模型成本属于后续独立阶段，不在本设计中预留虚假实现或隐藏开关。
