# AI 助手数据语义与平台查询

2026-10-27：本地采集数据分析增强，并接入用户提供的 VISSLM stdio MCP。

## 问题与修复

此前普通记录问答主要依赖字段/关键词查询，没有使用已有的记录向量检索；当规划结果未指定字段时，模型可能只收到名称而没有正文。旧上下文压缩还可能因内容过长删除整个 records 属性。字段名和少量样例值也不能解释状态编码、计量单位或业务口径。

现在分析请求会补入经清洗的描述和正文；按完整记录分配 24,000 字符证据预算，记录实际进入模型的条数。需要主题检索时，在已确定的项目、类型、记录及筛选范围内合并关键词与语义候选。向量候选最多 50 条，范围索引最多使用现有查询的 10,000 个 UID；该结果只用于分析证据，不作为全量统计。精确计数、列表和记录定位继续采用结构化查询。

本次也修复了混合来源列表查询中已验证的用户关键词被后备提词覆盖的问题，避免零命中被扩成整个本地数据集。分析结论区分事实、推断与建议，证据省略时显示范围说明；来源只保留实际交给模型的记录。

## 字段业务含义

在资产中心的「字段语义词典」中编辑字段，可维护：

- 业务定义，例如“实际交付日期，由验收完成动作写入”。
- 单位，例如“小时”“元”。
- 枚举值释义，每行 `原始值=业务含义`，例如 `1=处理中`、`2=已完成`。

这些内容和原有显示名、别名、角色一起进入查询规划。模型使用原始值查询，并依据已保存释义解释结果。含义不明确时仍需补充业务口径，不能仅凭字段名称自动证明因果关系。

人工语义保存在 `field_profiles.business_semantics_json`，按现有 scope_key 隔离。数据版本刷新会保留人工配置，并在首次重新读取画像时返回最新语义。未采集、没有本地字段画像的字段目前仅使用平台字段定义；平台返回的编码含义不会被自动猜测。

## 平台配置与提问

1. 在「系统配置 → 平台连接」保存平台地址、用户名、API Token 和登录密码。MCP 沿用这些配置，字段接口使用登录会话，记录接口同时使用现有 Token。
2. 在数据采集配置中选择需要查询的数据类型；已采集的类型也会进入可用目录，Project 始终可用于定位项目。
3. 「平台 MCP 服务入口」留空使用随应用打包的版本。需要使用自己的版本时，填写兼容的 `server.js` 绝对路径。
4. 在 AI 助手中输入 `@平台 分析项目 A 中当前需求的主要风险`，或「从 VISSLM 平台查询需求状态并分析」。为明确选择实时来源，后续问题也建议使用 `@平台`。

平台查询使用当前选择的本地或在线模型。流程为读取字段定义 → 校验查询字段/条件 → 查询数据 → 根据结果继续查询 → 分析回答。最多执行 6 步规划，每次操作只能选择 fields、query、answer。凭据由主进程注入，不进入模型上下文。

回答依据标为「平台实时记录」，点击可查看本次查询的正文快照、字段及读取时间。快照随会话保存，不自动导入本地数据中心；因此无需先采集才能分析平台数据。正文按长度限制省略，原始字段默认折叠，弹窗在暗色和亮色主题中使用应用主题变量并内部滚动。

## 当前范围

- 宿主只允许 `/Admin/Virtualization_ReadMember` 和 `/rest/items` 两个已核对的读取接口；不向模型开放 MCP 的任意 API 调用、上传、删除或业务修改。
- 支持单项目范围、实际字段过滤及多次查询。已有多项目、recordUids 或复杂 baseFilters 范围无法可靠映射时直接说明限制，不放宽范围。
- 每次接口响应最多选择 50 条记录进入 12,000 字符证据预算，最终回答的合并记录预算为 24,000 字符；分布按接口实际返回的全部行计算。接口没有全量/分页完成证明，因此只能描述“本次返回数据”，不能声称平台完整总数或排名。
- 超过 MCP 返回上限、非法结构、查询错误、无法确认字段时停止并说明原因。每次连接使用独立临时会话文件；任务结束或取消会关闭子进程并清理该会话。
- 目前没有接入关系、历史版本、工时等额外业务接口；涉及这些数据的问题需要后续逐一核对只读接口与语义。不会把接口目录中的数千个 API 自动当作可执行工具。

## 代码与验证

`src/main/assistant/record-analysis.ts` 和 `record-evidence.ts` 负责本地证据；`platform-mcp.ts` 负责受限 MCP 连接；`platform-analysis.ts` 负责多步查询与来源快照；`PlatformEvidenceModal.tsx` 展示证据。

`resources/visslm-mcp` 为用户提供的 MCP 源码快照（server.js、lib、api.json、package.json、README），仅复制运行所需文件，不复制原目录中的会话、配置或密钥。打包目标为 `resources/mcp/visslm-mcp`。

回归命令：

```text
npm run typecheck
npm run test:assistant-record-analysis
npm run test:platform-mcp-analysis
npm run test:assistant-orchestrator
npm run test:ai-assistant-global
npm run test:chat-context-safety
npm run smoke:project-management
npm run build
npx tsx scripts/smoke-platform-analysis-ui.ts
```

平台回归使用真实 MCP 子进程和模拟 HTTP 平台/模型；桌面 smoke 使用独立 Electron 用户目录，验证 IPC 路由、会话保存、来源弹窗、两种主题和桌面窗口内部滚动。它不连接实际平台，也不证明特定部署的字段、权限与业务口径已联调通过。
