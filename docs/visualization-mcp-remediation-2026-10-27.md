# 可视化 MCP 与质量链路整改记录

## 已实现

- 生成前由模型通过受控工具查询字段、业务解释和指标目录，试算 QuerySpec，并提交独立的分析目标契约。宿主绑定数据范围和不可变生成快照；查询不能扩大范围。
- 生成后检查目标覆盖、查询、结构和质量，并在隔离的 Electron 页面使用实际大屏组件渲染桌面预览；有明确问题时提供上一版草稿进行有限次数的局部修正。缺失字段、分母或度量时不得自动替换为其他指标。
- 支持截图消息跨 Ollama、OpenAI Chat、Anthropic 和 Responses 的传输转换。本地 Ollama 在确认模型有视觉能力后使用截图复核；其他提供方目前采用结构化渲染证据，不能称为视觉模型复核。
- 平台大屏从现有只读 MCP 获取字段与记录，保存在用户数据目录的独立快照；保存、重开、查询及字段选择均使用同一来源。平台未证明完整总量时明确标注，范围外记录被拒绝。快照持久化在本机，需与用户数据一同备份；本功能目前不提供自动清理策略。
- 提供独立 stdio MCP 工作进程用于快照字段和查询工具；应用内大屏草稿验证与预览仍由宿主管理。尚未实现任意第三方 MCP 服务的通用发现、协商或图表适配，未接入 AntV。

## 验证与边界

- 本地 `qwen3.8:27b` 使用合成记录完成了真实工具调用、试算、生成、截图检查与复核；四种桌面主题均通过渲染 smoke。测试数据和截图位于 `artifacts/dashboard-generation-remediation/`。
- 回归覆盖超过 100 个字段、范围隔离、样例隔离、指标替换拒绝、工具调用、目标覆盖、增量修正、截图消息传输、stdio MCP 和平台快照重开。平台集成测试使用真实 MCP 子进程与模拟 HTTP 平台；尚未对实际平台部署、字段配置及权限进行端到端验收。
- 尚未完成与整改前的相同数据、模型和问题集 A/B 评测，因此不能量化准确率提升或断言所有业务目标都被正确理解。指标契约仍由模型生成并由宿主检查，业务口径需要真实数据集进一步验收。
- 生成期快照在本地数据场景仅保留本次生成；平台来源使用持久快照以保证保存和重查一致。获取更新的平台数据需生成新大屏，避免旧组件与新快照混用。
