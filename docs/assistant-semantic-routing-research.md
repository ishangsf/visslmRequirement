# AI 助手语义路由重构与方案调研

调研日期：2026-10-27。范围：AI 助手的任务选择、来源选择、查询计划、交付形式与可视化子流程。主题样式、同步、权限和字段匹配不属于自然语言任务触发。

## 根因

原先并非模型独立理解后调用工具，而是多层规则反复修改含义：

1. 前端先用动作词、文件格式词截取原始问题，甚至直接复用历史证据并准备预览。
2. 路由器在模型前后根据业务词、编号、比较词、分组词重写 taskType/sourceMode/resultMode，并从句式恢复实体。
3. 分组路由直接绕过字段规划，把实体追加到全文搜索；字段名因此成为全文词。
4. 查询规划后又用“列出”“多少”等词覆盖分析、字段目录、聚合等操作；数量正则把交付物数量当记录数量。
5. 规划错误会退回关键词查询；不支持的字段/条件被静默丢弃，查询范围因此扩大。
6. 工具有结果即标为完成，未检查是否满足字段、分组与分析要求。列表渲染只列名称，用户要求的字段值可能丢失。
7. 可视化子流程继续根据图表词强制改写模型操作、选领域模板，另有规则蓝图先确定字段再限制模型。

这些偏差会随表达方式、语言、否定、复合任务而反复出现。仅调整某个词无法解决。

## 成熟实现方案

| 方案 | 已核对的机制 | 对本项目的启示 |
| --- | --- | --- |
| LangGraph / LangChain | 显式状态工作流、模型路由、工具循环；结构化输出的 schema 校验及错误反馈 | 让阶段边界和失败分支可检查，不用自然语言关键词作为状态转换条件 |
| OpenAI Agents SDK | 运行循环处理模型输出、工具结果、handoff 与最终输出；运行轮数上限；工具参数/结果 guardrails | 模型决定做什么，宿主执行权限与类型校验。工具执行成功不等于可以直接结束 |
| Anthropic 可组合 Agent 模式 | 从简单流程开始；路由、提示链、评估修正；执行时依赖工具的真实反馈 | 不必先引入重量框架；先修正语义和工具边界，并保留可审查的反馈 |

来源：[LangGraph workflows and agents](https://docs.langchain.com/oss/javascript/langgraph/workflows-agents)、[LangChain structured output](https://docs.langchain.com/oss/javascript/langchain/structured-output)、[Agents SDK running agents](https://openai.github.io/openai-agents-js/guides/running-agents/)、[Agents SDK tools](https://openai.github.io/openai-agents-js/guides/tools/)、[Anthropic Building effective agents](https://www.anthropic.com/research/building-effective-agents)。Anthropic 原文提示其工具生态已变化，本次仅采用架构原则，具体接口以当前文档为准。

## 采用方式

采用有界、类型化的语义工作流，复用现有 ModelClient、本地数据库、执行器、运行记录和取消机制。本次没有引入 LangGraph 或 Agents SDK 依赖，也没有将现有应用改成无边界的自主 Agent。

```mermaid
flowchart LR
  U[原始问题与用户历史] --> R[模型语义路由]
  R --> C[真实字段目录]
  C --> P[模型结构化查询计划]
  P --> V[字段、范围、来源和类型校验]
  V -->|失败，最多修正一次| P
  V -->|通过| E[受限工具执行]
  E --> Q[结果形状与覆盖验收]
  Q --> A[确定性数据清单或模型分析]
  A --> D[交付与可追溯证据]
```

保留的确定性代码只处理明确的 UI 选择、`@专家` 命令、类型/枚举、原文依据、真实字段映射、权限、作用域、SQL 参数、HTML 清洗和证据引用。它们不通过业务词猜测任务。

## 实施内容

- 自动路由的语义完全来自模型 JSON；任务/技能/来源组合不合法时回送错误，第二次失败即终止，没有关键词兜底。
- 始终把原始问题送入执行规划；resolvedQuestion 与路由实体只是提示，不能变成查询条件。
- records/mixed 都读取真实字段目录并规划，不再因分组请求跳过这一层。
- 查询操作与结果形式分离。`analysisRequired` 保留“清单加分析”的额外义务；限制数量需 `limitEvidence` 原文。
- 按字段真实值分组，支持多值拆分、去重、空值、完整筛选集计数和分页 UID。预览上限不等于总数。
- 字段聚合保留全文条件和字段条件；过滤未命中的记录不再被计为空值。
- 不认识的字段、不完整的筛选条件、无用户依据的值不再静默删除。执行后校验计数、字段和分组归属。
- 前端不再用文件格式/动作词截断问题或提前触发预览。预览只读取后端模型的 delivery 声明，实际生成仍走既有确认入口。
- 平台来源由模型的 recordOrigin 或显式 `@平台` 选择，不再根据“平台 + 查询”等词组触发。
- 可视化新建/修改、领域场景与角色由模型结构化选择；业务模板只接受已验证的场景 ID；图表类型操作不再被关键词重写。生成时从模型产生并校验的 QuerySpec 派生语义回执。
- 删除区域句式专用解析器。用户明确提供的“组名 → 编号”关系通过通用 `recordGroups` 计划表达，并验证原文依据、编号精确匹配及作用域；字段取值分组与显式编号分组分别建模。
- 字段别名冲突作为目录元数据提供给模型，不再扫描问题并强制改为澄清。明确选择的字段仍需唯一映射到真实字段。
- 执行进度读取类型化状态，不再因状态消息中出现“完成”而标记成功。前端不再使用追问词推断会话状态。
- 计划中的数据类型与界面选择范围取交集；界面选择多个类型时，不能吞掉计划中更窄的类型约束。

## 验证与边界

离线回归使用真实临时 SQLite 数据和脚本化模型输出验证宿主契约；它证明权限、范围、分组、修正与交付行为，不证明任意模型的理解正确率。单独的实时评测使用本机模型和合成数据，结果保存在 `artifacts/assistant-semantic-refactor/live-evaluation.json`。

不能承诺换任意问法都正确。剩余风险是模型计划语义仍可能有偏差、有限上下文与字段目录覆盖，以及超出工具能力的复合问题。对此应扩充带预期任务/条件/结果的评测集，用真实模型测量，再调整 schema、工具描述或模型能力；不得恢复关键词补丁。

超过清单预览上限时，正文明确披露展示/命中数量，分页视图保留索引；它不冒充全文已全部展开。模型或校验失败需要重试或返回具体错误，不伪装为成功，也不把内部错误转嫁成用户需要选内部枚举。

### 本轮验收

- `npm run typecheck` 与 `npm run build` 通过；构建保留已有的较大 chunk 提示。
- `npm run test:assistant-semantic` 汇总 30 个回归脚本，包含任务路由、否定和多语言、字段/数量契约、真实 SQLite 分组、作用域、组合分析、失败修正、交付预览、执行状态、可视化修改、领域模板及项目管理 smoke。详细结果为 `artifacts/assistant-semantic-refactor/regression.json`。
- `npx tsx scripts/smoke-platform-analysis-ui.ts` 使用隔离配置与合成数据，通过 Electron IPC、平台 MCP、证据详情、字段语义编辑、暗/亮主题、内部滚动和六个页面溢出检查；不读取生产数据。
- `npm run eval:assistant-semantic-live`：本机 `qwen3.8:27b`，4/4 通过。按分析人、按区域均得到 12 条记录的 2 个真实分组；状态聚合得到 8/4；明确禁止生成图表的解释请求保持普通问答。每项约 40–54 秒，属于当前本机配置的实测延迟，不是性能承诺。

离线测试验证执行契约；4 项真实模型评测只是本轮验收样本，不能替代更大规模的语义准确率评测。之后增加新工具或新数据域时，应添加相应任务契约及否定、改写、多语言、复合任务用例，不添加关键词触发分支。
